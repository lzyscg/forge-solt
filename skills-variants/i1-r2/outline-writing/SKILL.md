# 全篇执行大纲 Skill

你写的是供下游执行的规划，不是正文。目标是完整保留原文的因果、关系变化、反转、结局和必要余波，同时让每节信息短而可编译。

## S1. 忠实映射

先调用 `read_task_input`，显式传入 `field: source_text` 读取完整原文。只使用原文已有的人物、事件、因果、动机、数字、地点、程序机制和结局；不补写事实、对白或景物散文。

若原文已有 8–30 个编号分节，输出必须与原文分节 **一一对应、数量相同、顺序相同**，不得合并或拆分。若原文没有合格编号分节，才按主要状态变化划成 8–30 节：独立因果、关系位移、认知翻面、关键选择、结局或必要余波各有承载位置；纯移动、氛围和重复反应并入相邻节。

每节选一个模式：

- `快叙`：前史结果、移动或短连接；
- `冲突场景`：对白交锋、关系切割或权力变化；
- `悬疑发现`：新信息改变判断或淘汰旧解释；
- `现实情感`：生活处境、关系和迟来选择；
- `自定义`：以上均不适用。

按原文实际轻重选择 `细写 / 标准 / 轻过渡`，全篇至少使用两种。关键冲突、反转、选择和主要回报优先细写；完整变化闭环用标准；连接和短余波用轻过渡。

## S2. 唯一输出格式

每节只输出以下九个必填字段；值写成一个短语或短句，不解释标签、不复述同一事实。只有确有反转防泄底需要时，才追加 `信息控制`。

```text
1. 雨夜赴约
变化：林越准备赌局 → 林越来到摊牌门外
重点：P0 P001
展开：标准
模式：冲突场景
容量：对白轮次 2；动作反馈闭环 1；认知转折 1；事后余波 0
出场：林越、老周
目标：出示凭证并逼老周表态
冲突：凭证经不起核验，老周试图拖延
结束状态：林越推门看见第三个人
信息控制：不揭示第三人的身份
```

字段规则：

- `变化`：必须是 `起始状态 → 新状态`。
- `重点`：只能是 `bridge`、`P0 PNNN` 或 `P1 PNNN`。
  - P0 用于主要阅读动力、关键翻面、主要回报或结局；
  - P1 用于建立 P0 的必要触发、压力或余波；
  - bridge 只连接时空或状态，不带 ID。
- `展开`：只能是 `细写 / 标准 / 轻过渡`。
- `模式`：只能是 `快叙 / 冲突场景 / 悬疑发现 / 现实情感 / 自定义`。
- `容量`：逐字保留四项和顺序；数值上限依次为 8 / 4 / 4 / 2。只计本节真正需要的对白问答、动作反馈、认知转折和事后余波；没有就写 0。
- `出场`：逗号或顿号分隔；无人出场写 `无`。
- `目标 / 冲突 / 结束状态`：各写一个短句，只保留使本节可执行的内容。

## S3. 确定性编号与提交

从第 1 节按顺序输出，不做事后重排：

1. 小节标题依次写成 `1. 标题`、`2. 标题`……；原文合格分节一一对应时，小节号就是原文分节号。
2. 设置重点计数器 `k = 1`。每遇到一个 P0 或 P1，立即写 `P` 加三位 k（`P001`、`P002`……），随后 `k = k + 1`；bridge 不使用也不增加 k。P0/P1 共用这一个序列，ID 不重复、不跳号。
3. 最后一节必须是 P0 并兑现原文结局；结局前至少还有一个 P0。
4. 每节按固定顺序写全：`变化 / 重点 / 展开 / 模式 / 容量 / 出场 / 目标 / 冲突 / 结束状态`。

提交前只检查一次：节数是否为 8–30；若原文有合格分节是否数量相同；P ID 是否从 P001 连续无重复；是否至少两种展开；结局是否由最后一个 P0 兑现；是否遗漏必填字段或新增原文事实。不要增加说明、总结、表格或第二份大纲。

完成后调用 `complete_assignment`，只提交这一份完整大纲。
