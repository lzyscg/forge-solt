# R0.5 附录 — 判据三/四的 0 分是模型问题，不是提问方式问题

> 主报告：`notes/R0.5-REVIEWER-PROBE-REPORT.md`（其数字已逐项复算，全部重现）。
> 本附录追加两次实验，用同一批 29 条用例、同一个模型、同一组上下文，
> 只改**提问架构**。脚本 `probe/run-split.mjs` / `probe/run-decomp.mjs`，
> 原始输出 `probe/results-split.json` / `probe/results-decomp.json`。

## 0. 要回答的问题

主报告测出 D3（事实矛盾）、D4（停错地方）召回 0/3。有两种解释：

- **(a) 能力**：`deepseek-chat` 这一档看不见这两类缺陷。
- **(b) 提问方式**：主报告是「一次调用问四条判据、要一个总判决」，
  而 6 条 REVISE 里有 5 条是「每条判据恰好填一条 finding」——模型在**填表**。
  捆绑判决可能被最显眼的那条支配，另外两条根本没被认真执行。

(b) 若成立，结论就从「首版砍掉两条判据」翻成「判据要分开问」，功能不缩水。
所以必须先把 (b) 排除掉。

## 1. 实验一：四条判据拆开单问

一条判据一次调用，**上下文一字不删**（执行包/骨架/上一场/槽位目标/正文全给），
只把判据文本换成单条。同模型、同 temperature 0.2、同种子、每例跑 1 次。
116 次调用，0 个 ERROR/PARSE_ERROR。

| 缺陷 | 捆绑问 | 拆开单问（对口判据） |
|---|---|---|
| D1 承接断裂 | 3/3 | **3/3** |
| D2 心理解释 | 3/3 | **3/3** |
| D3 事实矛盾 | 0/3 | **0/3** |
| D4 停错地方 | 0/3 | **0/3** |
| 误打回（16 正例） | 0/16 | **0/16**（四条各自也都是 0/16） |
| 文风对照 ctl-29 | PASS | PASS（四条全 PASS） |

**召回一个没变。(b) 被排除。**

副产品：填表现象确实是捆绑提问的产物。拆开后 6 条反例里有 4 条**只有对口那一条判据点火**
（neg-14 只响判据一；neg-26/27/28 只响判据二），不再是四条齐发。
也就是说主报告 §2 的「finding 级精度 43%」是提问架构造成的，拆开就消失了——
但这只改善了 finding 的信噪比，**没有改善召回**。

代价：3.6 倍 token（116,087 → 417,016），每次调用反而更快（0.97s）。

## 2. 实验二：给判据三/四加强制对账步骤

拆开还救不回来，剩最后一个混淆：`review-skill.md` 的四条判据是**照抄写作 SKILL** 的
（计划 §2.3 的纪律）。而写作 SKILL 里判据二有「摄像机拍不拍得到」这种可判定规则加差/好例子，
判据三只有一句「别和别的场次撞设定」，判据四只有「停在哪里要兑现」——
后两条是**写给写作者的指令，不是写给审核者的检查步骤**。

于是把三/四改写成强制对账（**判据文本已改，与前两次实验不再可比**）：

- 判据三：先列出正文里的关键实体（人物/物件/时间/地点/金额），
  逐个核对「正文内部前后叫法是否一致」「与骨架是否一致」，再判决。
- 判据四：先把槽位目标里「停在哪里」的要求**原样抄出**，
  再把正文最后两段**原样抄出**，逐项比对，再判决。

58 次调用，0 个 ERROR/PARSE_ERROR。

| | 强制对账前 | 强制对账后 |
|---|---|---|
| 判据三 on D3 | 0/3 | **0/3** |
| 判据四 on D4 | 0/3 | **0/3** |
| 误打回（16 正例） | 0/16 | **0/16** |

## 3. 但这次失败的方式，比 0/3 这个数字有用得多

**模型照做了对账，做对了，然后照样盖章通过。**

判据三 · neg-16 的 inventory 原文（`results-decomp.json`）：

```json
{"entity":"转账凭证","正文里的说法":"凭证、欠条、布包",
 "骨架里的说法":"伪造的转账凭证","一致":true}
```

它**把注入的矛盾一字不差地写进了自己的工作区**——同一件东西被叫成凭证、欠条、布包——
然后在同一个 JSON 对象里填 `一致: true`。neg-17 同样：
`"正文里的说法":"转账凭证、这张票、这张空票、那张伪造的转账欠条、那张破了的转账欠条"` → `一致: true`。

判据四 · neg-19，要求项「林越独自站在（或坐在）**雨里**」判为兑现，它给的依据是：

> 林越在**桌边**站了很久，雨声从门外灌进来。

依据本身就否定了结论。neg-21 的要求项「林越站在岔路口做出一个**明确动作或回应**」判为兑现，依据是：

> 林越站着，没坐下，也没挪步……表现出**犹豫和未决**的状态。

（neg-21 还有一项依据凭空编出了「替朋友跑三个月渠道、后天交出假章」这段正文里没有的情节。
另外 6 条依据**没有一条**逐字出自正文，全是转述——`includes` 校验拦不住转述。）

**结论：不是感知失败，是判决失败。** 这一档模型有极强的 PASS 先验：
它能看见、能记录、能把矛盾写下来，但不肯把观察转成一个否定判决。

## 4. 「那就让代码去判」——试过了，不行

既然模型清点得对，能不能让它只出 inventory，由代码做比对（把判定权收回系统，
正是 AC-014 的思路）？我按两种机械规则验了：

**规则一：同一实体有多个别名 → 可疑。** 分不开——

| | 有多别名实体的例数 | 平均多别名实体数 |
|---|---|---|
| 16 条正例 | 9 | 2.2 |
| 3 条 D3 反例 | 3 | 3.3 |

散文本来就换着说法：转账凭证 → 这张票子 / 假票 / 空票 / 假回单，正例里别名最多的有 5 个。

**规则二：别名里出现骨架和上一场都没有的新称呼 → 可疑。**
几乎每一条都点火，正例也不例外（pos-01：老周→周老板、周哥）。

**没有一条机械规则能把 D3 和正例分开。** 物件被换名是语义问题，不是字符串问题。

## 6. 对 V0.2 的输入

> ⚠️ **本节第 1 条已被设计 D-28 推翻，保留原文只为记录推理过程。**
> 定案是**四条判据全部上线**：判据三/四误报为 0（不添乱），
> 且删掉就再也观察不到它们何时开始生效，其 0/3 反而成为一条可跟踪的基线。
> 读到这里不要据此去裁判据——以 V0.2 的 D-28 为准。

1. **首版审核只上判据一（承接）和判据二（可见行动）。** 这两条在三种架构下都测得准。
   判据三/四不是「提示词还没调好」，是这一档模型做不了——不要在 V0.2 里给它们留位置，
   也不要写成「后续优化提示词即可」。
2. **提问架构选拆开单问。** 召回一样，但 finding 噪声消失（对口判据独立点火），
   代价是 3.6x token——按主报告口径每场景约 4k 输入，拆成两条判据也就 8k，可以忽略。
   拆开还有个结构好处：每条 finding 天然带着它违反的判据，返修指令可以直接对上。
3. **误打回 0/16 是这套东西能自动跑起来的前提，且已被三次独立实验确认。**
   但它和 PASS 先验是同一枚硬币：这个审核员**只会漏，几乎不会冤**。
   返修循环因此可以放心接它的 REVISE，但**绝不能把「审过了」当成质量合格的证据**。
4. **D-27/D-32 的双预算仍然必须首版就有**，但理由变了：
   不再是「防止错误 finding 驱动无效返修」（拆开后噪声已降），
   而是「审核员只覆盖两类缺陷，循环可能在它看不见的问题上反复通过」——预算防的是无谓的轮次，
   不是发散。
5. **模型档位是唯一没试过的杠杆。** 全部结论只覆盖 `deepseek-chat`（v4-flash）。
   判据三/四要不要救，取决于换更强的档位测一次——这是下一个该做的实验，本附录未做。

## 7. 局限（沿用主报告口径）

每类缺陷 n=3，固定种子各跑 1 次，不重跑挑好看的。D3/D4 的 9 例全部来自「林越雨夜」
这一份执行包的重复生成，测的不是跨故事泛化。D4 的 neg-20 用例本身可疑
（删掉尾 3 段后，保留的结尾里老周已经给出了期限和条件，停点要求其实已兑现，
判 PASS 未必是错的）——扣掉它仍是 0/2，方向不变。

两次实验合计 651,049 token。
