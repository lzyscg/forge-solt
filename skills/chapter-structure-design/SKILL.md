# 章节结构设计 Skill

你的产出是**一棵槽位树**，不是章节正文。树里的每个内容槽位随后会交给别的
Agent 去填，它们看不到你的思考过程，只能看到你写在 `instruction` 里的话。
所以 `instruction` 的质量直接决定成品质量——它是你留给下游唯一的东西。

结构一旦通过校验就会整体落库，之后不能再改。被拒时系统会把**全部**违规一次给你，
你在同一次对话里修正后重新提交即可，不必重来。

## S1. 读懂执行包

先把【任务输入】读完，逐条回答下面四个问题。答不上来的，说明素材里没有，
不要自己补设定——补出来的设定会和后续章节冲突。

1. 本章要推进的**情节**是什么？（发生了什么事）
2. 本章结束时，人物状态相比开始**变了什么**？
3. 执行包里有没有点名必须出现的**具体事件或物件**？
4. 有没有写作约束（不出现小标题、场景分隔方式、结尾必须留下什么）？

第 3 条和第 4 条是硬要求。执行包里点名的东西如果没有对应的槽位承载，
成品一定漏项，而这类漏项在组装完成之后是补不回来的。

## S2. 切分场景

**场景数量由素材密度决定，没有固定值。** 判断标准只有一条：
一个场景 = 一次**地点或时间连续**的推进，中间不跳。素材撑不起四个场景就写三个；
把一件事硬拆成两个场景，会得到两段互相重复的正文。

给每个场景一个可判定的目标。对照这条来写 `instruction`：

- 差：「描写雨夜的气氛」——没有目标，没法判断写完没有。
- 好：「林越冒雨赴约，通过可见行动（反复确认怀里的凭证）建立他的紧张与孤注一掷，
  结尾停在他推门看见老周的瞬间。」——有动作、有目的、有终点。

`instruction` 里要写清楚三件事：**这一场发生什么、要建立或改变什么、停在哪里**。
最后一件最容易漏，而它正是下游衔接上一场的依据。

## S3. 依赖与顺序

这里有两个**互不相同**的字段，混淆它们是最常见的设计错误：

- `order`：成品里的**阅读顺序**。同一个父节点下不能重复。
- `dependsOn`：生产时的**先后顺序**。列在这里的槽位会先被写完，
  本槽位生产时能读到它们的正文。

规则：

1. 规划类槽位（章节骨架）**排在所有场景之前生产**，场景全部 `dependsOn` 它。
2. 场景之间**链式依赖**：第二场 `dependsOn` 第一场，第三场 `dependsOn` 第二场。
   这样每一场都能读到上一场的结尾状态，衔接才接得上。
3. **标题必须 `dependsOn` 章节骨架。** 标题在成品里排最前（`order` 小），
   但它要概括的是整章内容——不依赖骨架就意味着写标题时它什么都还没看到，
   只能照着执行包再猜一遍。`order` 靠前和 `dependsOn` 靠后并不矛盾，
   这正是两个字段分开的原因。
4. 依赖不能成环，不能依赖容器槽位，不能依赖自己。

## S4. 常见的结构设计失误

（本节不自动注入，需要时用 `read_skill_section` 读取）

- **场景粒度过细**：把「进门」「落座」「开口」拆成三个场景。它们是同一次连续推进，
  应当合成一场。表现是成品里出现大量过场文字。
- **instruction 写成了正文**：在 `instruction` 里直接写出人物对白。
  下游拿到后只会照抄，等于你替它写了，而你写的时候还看不到上一场。
- **漏掉结尾状态**：最后一个场景的 `instruction` 没说清结束时留下什么。
  执行包若要求「结尾必须留下可承接的状态」，这一条要原样落到最后一场的 `instruction` 里。
- **给容器槽位挂依赖**：容器不产出内容，依赖它永远等不到。

## S5. 提交前自检

提交前逐条过一遍。这几条是校验最常拦下的：

- [ ] 有且只有**一个**根槽位，且它的类型是容器类型，`parentId` 为 `null`。
- [ ] 每个 `id` 都是小写字母开头、只含小写字母/数字/下划线，且全表唯一。
- [ ] 每个 `type` 都出现在【可用槽位类型】里，一个字都不能差。
- [ ] 同一个 `parentId` 下的 `order` 互不相同。
- [ ] 每个内容槽位的 `instruction` 非空，且写明了「发生什么、改变什么、停在哪里」。
- [ ] 至少有一个内容槽位。
- [ ] `dependsOn` 里的 id 都真实存在、都是内容槽位、没有成环。
- [ ] 标题槽位 `dependsOn` 了章节骨架（S3 第 3 条）。
- [ ] 槽位总数与树深度都没超过【结构约束】给的上限。

自检完成后调用 `complete_assignment` 一次提交完整结构。
系统不保存部分结构，分批提交只会让前一批丢失。
