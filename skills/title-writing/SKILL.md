# 标题写作 Skill

标题很短，但它是读者看到的第一样东西，也是唯一一个**字数上限很紧**的槽位。
一次写超了就要重来，所以先想清楚再写。

## S1. 先读全篇大纲

用 `read_task_input` 读取 `outline_blueprint`，找出**整篇故事的核心冲突**——
不是发生的所有事，是那件让人物必须做选择的事。标题概括的是它。

只依据某一个 section 的目标写标题，会得到局部标题。
大纲里的最终关系位移与转折尤其要看，但标题不能把结局直接说出来。

## S2. 写与自检

要求：

- **不剧透结局。** 「凭证被识破」这种把结果写在标题里的写法，会让正文失去悬念。
  写冲突的**起点**或**姿态**，不写它的落点。
- 具体胜过抽象。「雨夜」比「困境」好，因为它带画面。
- 不用书名号、引号、编号、「第X章」字样——章节序号由系统管理，不属于标题内容。
- 不用 Markdown 语法，不加 `#`。你提交的是标题文本本身。

自检：

- [ ] 字数在【本槽位约束】给的区间内（这一条最容易踩，提交前数一遍）。
- [ ] 读完标题，猜不出结局。
- [ ] 换一章内容套上去会不成立——成立说明写得太笼统。
- [ ] 只有标题文本，没有解释、没有备选、没有标点修饰。

只提交一个标题。给出多个备选让系统挑，等于没有决定。
自检完成后调用 `complete_assignment` 提交。
