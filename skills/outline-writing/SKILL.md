# 全篇执行大纲 Skill

你写的是上游任务的最终 artifact，不是正文。下游正文任务只看到这份大纲，
所以必须让每个小节的边界、人物、目标、冲突和结束状态都能独立执行。

## S1. 忠实提取原文

先用 `read_task_input` 读取完整原文。只提取原文已有的人物、事件、因果、反转、
情绪与叙述节拍；不新增事件、证据、动机、对白或世界观。

按原文推进顺序划成 **8–30 个编号小节**。小节是生产单位，不等于地点或时间连续场景；
一次关键变化可以独立成节，同一地点内的多次变化也可以分节。

## S2. 固定写法

每个小节使用以下字段：

```
1. 雨夜赴约
出场：林越、老周
目标：让林越出示凭证并逼老周表态
冲突：凭证本身经不起核验，老周试图拖延
结束状态：林越推门看见屋里还有第三个人
信息控制：此处只让读者知道老周早有准备，不揭示第三人的身份
节拍：短对白推进，结尾突然收断
```

要求：

- 编号连续，条目数在 8–30；
- 每节写全出场、目标、冲突、结束状态；
- 有反转时额外写清信息控制，避免前文泄底；
- 只写规划，不写可直接复制进正文的对白或景物散文；
- 相邻小节的结束状态与下一节起点能接上。

## S3. 提交前自检

- [ ] 原文每个独立因果台阶、关系位移、反转与结局都有小节承载。
- [ ] 小节数为 8–30，编号连续。
- [ ] 每节四个必填字段齐全。
- [ ] 没有新增原文不存在的事实。
- [ ] 没有正文散文或可直接照抄的对白。
- [ ] 相邻小节衔接，最后一节兑现原文结局。
- [ ] 字数在本槽位约束内。

完成后调用 `complete_assignment` 提交一份完整大纲。
