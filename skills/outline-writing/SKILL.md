# 章节骨架 Skill

你写的东西**不会进入成品**，它只被后面的场景槽位读取。
这决定了它的写法：清单胜过散文，明确胜过好看。
一句写得很美但没说清人物目标的骨架，对下游毫无用处。

## S1. 这份骨架要回答什么

下游写每一场时，只能看到三样东西：本槽位的 `instruction`、依赖槽位的正文、
以及这份骨架。所以骨架必须替它们回答：

- 这一场**谁在场**？
- 这一场要达成什么**目标**？
- 阻力是什么——**冲突**在哪？
- 这一场结束时，局面**变成了什么样**？

四问缺一，下游就得自己编，而两个不同的场景槽位各编各的，人物就会前后不一致。

## S2. 写法

按场景分条，每条一段，用固定的字段顺序，便于下游定位：

```
场景一 · 雨夜赴约
出场：林越、（老周仅在结尾隔窗出现）
目标：让林越的孤注一掷成为可见的行动，而不是心理描写
冲突：他自己知道凭证经不起看，但已经没有退路
结束状态：他推开茶楼的门，与老周目光相接
```

不要写对白，不要写景物描写，不要替下游想句子——那是场景槽位的工作。
你多写一句正文，下游就少一分自由，而它比你更清楚上一场的结尾长什么样。

## S3. 自检

- [ ] 场景条数与结构里的场景槽位数**一一对应**，不多不少。
- [ ] 每条都写全了出场、目标、冲突、结束状态四项。
- [ ] 相邻两条的「结束状态」与下一条的开场对得上。
- [ ] 全篇没有正文散文，没有对白。
- [ ] 字数在【本槽位约束】给的区间内。

自检完成后调用 `complete_assignment` 提交。
