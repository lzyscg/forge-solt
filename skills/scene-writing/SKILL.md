# 场景写作 Skill

你只写**一个小节**。它前后都有别的小节，成品按槽位顺序首尾相接拼起来——
没有人会在事后替你把接缝抹平。所以衔接是你的责任，不是组装环节的责任。

## S1. 读懂本场目标

读【本槽位目标】。它会告诉你这一节发生什么、要建立或改变什么、停在哪里。
这三件都要在正文里兑现，尤其是**停在哪里**：它是下一节的起点，
你没停在那儿，下一节就会从一个不存在的局面往下写。

再用 `read_task_input` 读取 `outline_blueprint`，确认本节的出场、冲突、信息控制和节拍。

## S2. 读取前置状态

用 `read_slot` 读依赖里的上一个小节，**只看它的结尾**：
人在哪、手上有什么、刚说完什么、气氛是什么。

你的首段必须从这个状态接着往下走。不要重述上一节发生过的事——
成品里它就在你上面几行，读者刚看完。

如果依赖里没有上一个小节（你是第一节），首段负责建立时间、地点与人物处境。

## S3. 怎么写

**用可见的东西推进。** 判断标准：如果一句话描述的内容摄像机拍不到，
它就是解释而不是事件。

- 差：「他很紧张，知道这次赌注很大。」
- 好：「他在第三个路口停下来，解开一粒扣子，指尖探进去摸那张纸的折角。」

第二句让读者自己得出「他很紧张」，而且顺带交代了他带着什么。
心理解释可以有，但它是调味，不是主食——每写一段解释，先确认前面已经有事件支撑它。

其他要求：

- 对白要有信息量。寒暄、重复上一句、纯粹为了填字数的对话都删掉。
- 场景内部用空行分段，**不要使用 Markdown 小标题**（`#` 开头的行会被校验拒绝）。
- 小节正文只交内容，不另写 `1.`、`2.` 或 Markdown 小标题；编号由槽位顺序和最终装配表达。

## S4. 需要更多篇幅时怎么办

（本节不自动注入，需要时用 `read_skill_section` 读取）

字数不够，几乎总是因为事件不够，而不是描写不够。加描写会得到一段注水的正文。
正确的做法是加**具体动作与具体物件**：他做了什么、碰了什么、对方怎么回应。
每多一个具体物件，就多一处可以被下一场承接的抓手。

## S5. 需要压缩时怎么办

（本节不自动注入，需要时用 `read_skill_section` 读取）

先删心理解释，再删环境描写，最后才删对白。
被删掉的心理解释如果确实必要，把它改写成一个动作。

## S6. 提交前自检

- [ ] 首段与上一小节的结尾状态接得上（第一节除外）。
- [ ] 本节目标里的三件事——发生什么、改变什么、停在哪里——都兑现了。
- [ ] 正文里**没有任何以 `#` 开头的行**（这条是硬性校验，会被直接拒绝）。
- [ ] 字数在【本槽位约束】给的区间内。
- [ ] 没有出现「第一场」「场景二」之类的结构标记。
- [ ] 通篇读一遍：是不是靠事件在推进，而不是靠形容词。

自检完成后调用 `complete_assignment` 提交正文。
只提交正文本身，不要附带说明、不要解释你的写作思路——
需要说明的话用 `report_work`。
